## Checking the next official release

```sh
npm run check:official
node scripts/check-official-compatibility.mjs --version=0.2.1-rc.5
```

The default command reads the official npm package's current `latest` metadata.
Missing access, a registry failure, mismatched declarations and an untested exact
version all fail. It does not modify the compatibility list, publish packages or
schedule itself. Run the isolated SDK matrix and exact-archive official Host checks
before adding a future version to `compatibility-manifest.json`, the package
declarations and the bounded release checker.

## Publication boundary

The existing `.github/workflows/npm-release.yml` is unchanged. It uses manual
dispatch on canonical `main`, validates locked source without hooks, packs a public
allowlist, hashes immutable artifacts, and grants OIDC only to the explicit publish
job. Public npm 0.1.3-preview.1 has GitHub Actions Trusted Publisher provenance for
that exact repository/workflow. Workflow dispatch and published archive hashes are verified separately from the local checks above.

No GitHub Release-assets workflow exists in the current public repository. The
existing v0.1.2 and v0.1.0 assets remain public historical releases; they do not
contain this compatibility preview. An ongoing official-version check must be
coordinated externally or added to a workflow after the required workflow-scope
authorization is available.
